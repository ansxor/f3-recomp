# ES5510 (ESP): the effects DSP

The Ensoniq ES5510, or ESP, processes the effects path. This page explains host latches, instruction fields, delay memory and the execution pipeline.

Sources: [es5510.hpp](https://github.com/ansxor/f3-recomp/blob/main/runtime/third_party/audio/es5510.hpp) and [es5510.cpp](https://github.com/ansxor/f3-recomp/blob/main/runtime/third_party/audio/es5510.cpp).

This page documents the MAME-derived software model. Pipeline and arithmetic
rules are implementation behavior, not independently measured silicon behavior.
Device replay and whole-game waveform comparisons have different evidence
boundaries; see [audio comparison](/developer/testing/audio-compare).

## What the chip does

The ES5510 is a digital signal processor. It runs a loaded program during each enabled PCM frame.

OTIS pairs 1–3 enter its six serial inputs. Its final stereo pair enters the mixer. OTIS pair 0 bypasses the DSP.

The sound driver loads the DSP program through a host interface on the sound CPU bus. The docs say that the driver selects one of 13 effect configurations and loads the program of that configuration. See `docs/SOUND-DRIVER.md` for the ROM addresses.

The class is `f3rt::ES5510` in `runtime/third_party/audio/es5510.*`. It is a port of the MAME core of Christian Brunschen.

## Data in the chip

| Member | Size | Meaning |
|---|---|---|
| `m_gpr` | 192 (`0xc0`) values of 24 bits | General-purpose registers. |
| `m_instr` | 160 values of 48 bits | The program. |
| `m_dram` | `DRAM_SIZE` = 1,048,576 values of 16 bits | Delay memory (2 MiB). |
| `ser0l` ... `ser3r` | 8 values of 16 bits | Serial audio ports. |
| `machl` | 48 bits (`int64_t`) | Multiply-accumulate result. |
| `dlength`, `abase`, `bbase`, `dbase`, `sigreg` | 24 bits | Special registers for RAM addressing and mode. |
| `ccr`, `cmr` | 8 bits | Condition flags and condition mask. |

The flags are `N` (`0x80`), `C` (`0x40`), `V` (`0x20`), `LT` (`0x10`) and `Z` (`0x08`). The mask register also has a `NOT` bit (`0x04`).

## The host interface

The sound CPU reaches the chip at `0x260000` - `0x2601ff`. Only odd addresses carry data. `Audio` calls `host_r` and `host_w` with the register number `(address >> 1) & 0xff`.

| Register | Name in code | Action |
|---|---|---|
| `0x00` - `0x02` | `gpr_latch` | A 24-bit value, written one byte at a time (high byte first). |
| `0x03` - `0x08` | `instr_latch` | A 48-bit instruction, six bytes. |
| `0x09` - `0x0b` | `dil_latch` | Data input from delay memory. |
| `0x0c` - `0x0e` | `dol_latch` | Data output to delay memory. |
| `0x0f` - `0x11` | `dadr_latch` | Delay RAM address. A write to `0x0f` starts a RAM access. |
| `0x12` | Host control | Bit 1 clears the delay RAM, but only when the chip is halted. |
| `0x14` | `ram_sel` | Bit 7 chooses read (1) or write (0) for `dadr_latch`. |
| `0x18` | `host_serial` | Stored. |
| `0x1f` | Halt enable | If the halt pin is on, the chip enters the halted state. |
| `0x80` | Read select | Copies instruction `data` into `instr_latch` (if less than `0xa0`) and a register into `gpr_latch`. |
| `0xa0` | Write select, GPR | Writes `gpr_latch` to register `data`. |
| `0xc0` | Write select, instruction | Writes `instr_latch` to instruction `data`. |
| `0xe0` | Write select, both | Does both writes. |

A write to register `0x0f` with `ram_sel` clear stores `dol_latch >> 8` into delay RAM. With `ram_sel` set it loads `dil_latch` from delay RAM.

The driver loads a program like this: write six instruction bytes, write the select register `0xc0` with the instruction number, and repeat for each instruction. It loads registers the same way with the GPR latch and the select register `0xa0`.

The table describes host writes and latch roles. Host reads have narrower behavior:

- Registers `0x00..0x0a` return GPR, instruction and DIL latch bytes.
- Register `0x0b` returns zero. DOL registers `0x0c/0x0d` return upper bytes; `0x0e` returns `0xff`.
- Registers `0x0f..0x11` return address-latch bytes.
- Host control read `0x12` returns zero. Test PC read `0x16` returns `0x27`.
- All other host reads return zero.

Write the low and middle address-latch bytes before `0x0f` when selecting a new complete address. The high-byte write triggers the access immediately.

Instruction select commits require destination below `0xa0`. GPR writes use `write_reg`, including its special-register mappings.

Numbers `192..233` read as zero and ignore writes. Constants `252..255` also ignore writes.

`write_to_dol` converts a 24-bit result to 16 bits by shifting right eight. Its two-entry output queue feeds delayed RAM writes.

No external DSP I/O device is attached. I/O reads return zero, and I/O writes do not write delay RAM.

### Register numbers `read_reg` and `write_reg` know

| Number | Meaning |
|---|---|
| `0` - `191` | General-purpose registers. |
| `234` - `241` | Serial ports: `ser0r`, `ser0l`, `ser1r`, `ser1l`, `ser2r`, `ser2l`, `ser3r`, `ser3l`. The value is the 16-bit sample times 256 (24-bit format). |
| `242`, `243` | Low and high half of `machl`. |
| `244` | `dil`. A write sets the delay memory size from the number of low one-bits. |
| `245` - `249` | `dlength`, `abase`, `bbase`, `dbase`, `sigreg`. |
| `250`, `251` | `ccr`, `cmr`. |
| `252` - `255` | Constants `0x00ffffff`, `0x00800000`, `0x007fffff`, `0`. |

## Serial ports and the mixer

The mixer in `Audio::generate_one_frame` writes `ser_w(0..5)` with the six ES5505 channels of pairs 1 to 3. The program reads them as registers 234 to 239. The program writes the main output to the registers 240 and 241 (`ser3r` and `ser3l`). The mixer reads `ser_r(6)` (`ser3l`, left) and `ser_r(7)` (`ser3r`, right).

## The instruction format

An instruction has 48 bits. The code in `execute_run` takes these fields:

| Bits | Field |
|---|---|
| 0 - 2 | Not used by `execute_run`. |
| 3 - 5 | RAM control (index 0 to 7). |
| 6 | Accumulate (`1` adds the product to `machl`). |
| 7 | Skippable (the condition flags can skip the instruction). |
| 8 - 11 | Operand select. It chooses where the ALU and the multiplier read and write (register, delay output, or both). |
| 12 - 15 | ALU operation. |
| 16 - 23 | ALU register A. |
| 24 - 31 | ALU register B. |
| 32 - 39 | Multiplier register C. |
| 40 - 47 | Multiplier register D. |


### Operand-select combinations

The four columns identify ALU source, ALU destination, multiplier source and multiplier destination.

| Select | ALU source | ALU destination | MAC source | MAC destination |
|---:|---|---|---|---|
| 0 | Register | Register | Register | Register |
| 1 | Register | Register | Register | Delay |
| 2 | Register | Register | Register | Both |
| 3 | Register | Register | Delay | Register |
| 4 | Register | Register | Delay | Both |
| 5 | Register | Delay | Register | Register |
| 6 | Register | Delay | Delay | Register |
| 7 | Register | Both | Register | Register |
| 8 | Register | Both | Delay | Register |
| 9 | Delay | Register | Register | Register |
| 10 | Delay | Register | Register | Delay |
| 11 | Delay | Register | Register | Both |
| 12 | Delay | Register | Delay | Register |
| 13 | Delay | Delay | Register | Register |
| 14 | Delay | Both | Register | Register |
| 15 | Delay | Both | Delay | Register |

Delay sources use DIL shifted into the 24-bit domain. A register destination uses A for the ALU and C for the multiplier.

The multiplier's D operand remains a register. For two-operand ALU operations, B remains a register.

### ALU operations

`ALU_OPS[16]` lists the operations. The first eight use two operands. The next seven use one operand.

| Code | Name | Code | Name |
|---|---|---|---|
| `0x0` | `ADD` (saturates) | `0x8` | `ABS` |
| `0x1` | `SUB` (saturates) | `0x9` | `MOV` |
| `0x2` | `ADDU` | `0xa` | `ASL2` |
| `0x3` | `SUBU` | `0xb` | `ASL8` |
| `0x4` | `CMP` | `0xc` | `LS15` |
| `0x5` | `AND` | `0xd` | `DIFF` |
| `0x6` | `OR` | `0xe` | `ASR` |
| `0x7` | `XOR` | `0xf` | `END` |

`END` marks the end of the program.

### RAM control

The three bits at 3 - 5 choose one of eight RAM cycles from `RAM_CONTROL[8]`.

| Index | Cycle | Address source |
|---|---|---|
| 0 | Read | Delay memory (`dbase` + offset, modulo `dlength`) |
| 1 | Write | Delay memory |
| 2 | Read | Table A (`abase` + offset) |
| 3 | Write | Table A |
| 4 | Read | Table B (`bbase` + offset) |
| 5 | Dump FIFO and read | Delay memory |
| 6 | Read | I/O |
| 7 | Write | I/O |

The offset is the value of the general-purpose register with the same number as the program counter. For the I/O cycles the address is `offset & 0x00fffff0`, and no delay-RAM access happens.

## Running a program

The function `run_once()` makes one sample. It does these steps:

1. It sets the halt pin off and calls `execute_run(1)`. If the chip was halted, this call only wakes it: the state becomes running and `pc` becomes 0.
2. It sets the halt pin on.
3. It calls `execute_run(1)` again until the state is `STATE_HALTED`. A safety counter stops the loop after 200 passes.

One call to `execute_run(1)` executes one instruction when the modeled chip is running. The program counter `pc` starts at 0. The model implements a pipeline, so `execute_run` does these actions in each step:

1. Take the RAM cycle of two steps ago. If it is not a write, load `dil` from delay memory.
2. Compute the RAM address for this instruction.
3. Decide whether the skip condition applies: `(ccr & cmr & FLAG_MASK) != 0`, inverted when the `NOT` bit is set.
4. Finish the multiplier of the previous instruction: product of the sign-extended 24-bit values `cValue` and `dValue`, shifted left by `mulshift` (2, or 1 if `sigreg` bit 22 is set). If `accumulate` is set, add `machl`. The result is 48 bits. An overflow beyond 48 bits sets `mac_overflow` and saturates the 24-bit result.
5. Start the multiplier for this instruction.
6. Finish the ALU operation of the previous instruction and write the result to a register, the delay output (`dol`), or both.
7. Start the ALU operation for this instruction. If it is `END`, `alu_operation_end` runs.
8. Write the delay output of the previous RAM cycle to delay memory.
9. Increase `pc`.

`alu_operation_end` does three actions. If the halt pin is on, it sets the state to `STATE_HALTED` and clears host-control bit 2. It decreases `dbase` by `memincrement` and wraps to `dlength` when it goes below 0. If the state is still running, it sets `pc` to 0.

A valid program with END normally completes within `run_once`. The 200-pass safety limit prevents an endless host loop.

The function does not throw if that limit expires. It does not guarantee that an invalid or overlong program reaches END.

END decreases `dbase` by `memincrement` and wraps a negative value to `dlength`. Delay addresses also apply `memmask`, `memshift` and DRAM masking.

### Skipped instructions and flags

If an instruction is skippable and the skip condition is true, the multiplier result and the ALU result are not written. A skippable instruction does not update the flags. The exception is `CMP`. It always runs, because it only sets flags.

## How the DUART halts the chip

The DUART output pin OP6 drives the ESP halt pin. `Audio::Impl` connects them:

```cpp
m_duart.set_outport_callback([this](uint8_t output_pins) {
    m_esp_halted = (output_pins & 0x40) != 0;   // OP6
});
```

After a reset the DUART reports `0xff`, so `m_esp_halted` is true. In `generate_one_frame`, `run_once()` runs only when `!m_esp_halted`. A halted ESP leaves its output ports unchanged. The sound driver clears the halt to run the DSP program. The DUART page explains the set and reset output registers: [DUART and volume](/developer/runtime/audio/duart-and-gain).

## Reset and state

`ES5510::reset` sets PC to zero, state to running, SIGREG to zero, and multiplier shift to two.

It clears host latches, GPRs, instruction memory, delay RAM and the three RAM pipeline records. Host control becomes `0x04`.

It preserves serial ports and other special state, including the MAC, delay-output queue, ALU and multiplier pipeline records.

It also preserves the internal halt-pin flag. The board's separate `m_esp_halted` flag gates `run_once` calls through the DUART output callback.

`Audio::reset_board` calls it. CPU-line reset does not. Existing checks distinguish retained CPU-line state from cleared board-reset GPRs.

Snapshots include serial and special registers, latches, ALU/MAC/RAM pipeline state, GPRs, instructions and the complete 2 MiB delay RAM.

Loading restores that state without calling reset. It does not reload a program from ROM.

See [sequences](/developer/runtime/audio/sequences) for effects-worker selection and [tracing](/developer/runtime/audio/tracing) for offline host-latch reconstruction.
