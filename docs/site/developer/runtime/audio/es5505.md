# ES5505 (OTIS): the sample voices

The Ensoniq ES5505, or OTIS, plays sampled sound through 32 voices. This page explains registers, sample addressing, filters, loops and banks.

Sources: [es5505.hpp](https://github.com/ansxor/f3-recomp/blob/main/runtime/third_party/audio/es5505.hpp) and [es5505.cpp](https://github.com/ansxor/f3-recomp/blob/main/runtime/third_party/audio/es5505.cpp).

Register, voice, and filter descriptions below refer to the MAME-derived runtime
model. Matching replayed MAME device output is compatibility evidence, not an
independent measurement of an ES5505 or the board's analog output.

## What the chip does

The ES5505 reads signed 16-bit words from sample ROM. Each voice has an address accumulator, pitch step, filter and two volumes.

Linear interpolation combines neighboring words. The chip adds active voices into four stereo output pairs.

The sound driver does not send audio data to the chip. It writes control registers. It changes pitch, filter and volume many times in a second. The chip does not make a volume envelope by itself. The driver makes the envelope in software.

In this runtime `class ES5505` holds 32 `Voice` structures (`MAX_VOICES = 32`) and the generator. `Audio::Impl` owns one `m_es5505` and constructs it with the default master clock 15,238,090 Hz.

## The register interface

The chip has 16 registers on the bus. They are 16-bit words at `0x200000` + 2 * register. A write can use one byte. The code handles the byte lanes with `mem_mask`.

The register `PAGE` (number `0xf`) selects which set of registers the other 15 offsets show.

| `PAGE` value | What the offsets show |
|---|---|
| `0x00` - `0x1f` | Low page. The control registers of voice number `PAGE & 0x1f`. |
| `0x20` - `0x3f` | High page. The filter memory of voice `PAGE & 0x1f`. |
| `0x40` and above | Test page. `SERMODE`, ACT, IRQV and PAGE remain available. |

The code keeps `m_current_page` (7 bits, `data & 0x7f`). The functions `reg_read_low`, `reg_read_high`, `reg_read_test`, `reg_write_low`, `reg_write_high` and `reg_write_test` handle the three page types.

### Low page registers

| Offset | Name | Meaning |
|---|---|---|
| `0x0` | `CR` | Control register. See the bit table below. |
| `0x1` | `FC` | Frequency count. Bit 0 is ignored. It sets the step size per output sample. |
| `0x2` | `START` high | High bits of the start address. |
| `0x3` | `START` low | Low bits. The low five bits are ignored. |
| `0x4` | `END` high | High bits of the end address. |
| `0x5` | `END` low | Low bits. The low five bits are ignored. |
| `0x6` | `K2` | Filter coefficient 2. The low four bits are ignored. |
| `0x7` | `K1` | Filter coefficient 1. The low four bits are ignored. |
| `0x8` | `LVOL` | Left volume. Only the high byte of the word is used. |
| `0x9` | `RVOL` | Right volume. Only the high byte of the word is used. |
| `0xa` | `ACC` high | High bits of the current address (accumulator). |
| `0xb` | `ACC` low | Low bits of the current address. |
| `0xd` | `ACT` | Number of active voices minus 1 (5 bits). |
| `0xe` | `IRQV` | Interrupt vector. A read returns the value and clears it. |
| `0xf` | `PAGE` | Page select. |

An address is a word address in the sample ROM with fraction bits. The accumulator keeps 20 integer bits and 9 fraction bits. The implementation adds 2 more internal bits (`ADDRESS_ACC_MASK = 0x7fffffff`). The helper `get_address_acc_shifted_val` moves a register value into this format.

The effective step per output sample is `FC / 1024` words, according to `docs/SOUND-DRIVER.md`. A value of `0x400` plays one ROM word for each output sample.

### The control register `CR`

The enum at the top of `es5505.cpp` names the bits.

| Bit | Mask | Name | Meaning |
|---|---|---|---|
| 0, 1 | `0x0003` | `STOP0`, `STOP1` | Either bit prevents PCM generation and accumulator movement. Pending IRQ state can still be processed. |
| 2 | `0x0004` | `LEI` | Loop end interrupt. The generator does not use it. |
| 3 | `0x0008` | `LPE` | Loop enable. |
| 4 | `0x0010` | `BLE` | Bidirectional loop enable. |
| 5 | `0x0020` | `IRQE` | IRQ enable. A voice end sets the `IRQ` bit. |
| 6 | `0x0040` | `DIR` | Direction. 1 means backward. |
| 7 | `0x0080` | `IRQ` | Voice interrupt pending. |
| 8, 9 | `0x0300` | `CA0`, `CA1` | Output pair (0 to 3). |
| 10, 11 | `0x0c00` | `LP3`, `LP4` | Filter mode (0 to 3). |
| 13 | `0x2000` | `CMPD` | Compressed sample format. |
| 14, 15 | `0xc000` | `BS0`, `BS1` | Bank select. |

Reads of `CR` always return the upper four bits as 1 (`control | 0xf000`). Writes keep those four bits at 1.

::: warning
The enum names `CMPD`, but the PCM generator does not decode compressed samples. Its computed `m_ulaw_lookup` table is unused.

The upper CR bits are forced high, not active format or bank selectors in this model. Board bank registers supply sample banks.
:::

### High page registers

The high page gives the filter memory of the voice. A driver can read and write it.

| Offset | Name |
|---|---|
| `0x1` | `O4(n-1)` |
| `0x2` | `O3(n-1)` |
| `0x3` | `O3(n-2)` |
| `0x4` | `O2(n-1)` |
| `0x5` | `O2(n-2)` |
| `0x6` | `O1(n-1)` |

The read of offset `0x6` has a special case for Taito F3 games. The source comment says so. If the voice is stopped, the code first loads `o1n1` with the raw sample word at the voice address. The test in `runtime/check.cpp` checks this behavior: a read of the high page of a stopped voice returns the sample word.

## Banks

The chip has a 20-bit word address. The sample ROM on the F3 board is larger. The board adds a bank register for each voice at `0x300000` + 2 * voice. A write calls `ES5505::set_voice_bank(voice, (value & m_bank_mask) << 20)`. The value is a word offset.

`Audio::load_sample_rom` sets `m_bank_mask`. For a ROM of at least 2 MiB the mask is `size / 0x200000 - 1`. The Land Maker sample region has 16 MiB, so the mask is 7. Eight banks of 1 M words (2 MiB) each fill the region.

`read_sample` makes the final address:

```cpp
full_addr = (m_voice_bank[voice->index] + word_addr) & (m_rom_words - 1);
return m_rom[full_addr];
```

This works because `m_rom_words` is a power of two (8 M words for 16 MiB).

### How the ROM chips fill the region

`RomSet::load` in `runtime/rom.cpp` builds the 16 MiB `samples` array. The array starts as zeros. The code places three 2 MiB chips with the helper `lane(region, bytes, offset, stride = 2)`:

| Chip | Start offset in the array |
|---|---|
| `e61-04.38` | `0x400000` |
| `e61-05.39` | `0x800000` |
| `e61-06.40` | `0xc00000` |

Each chip fills every second byte, the even bytes. The even byte is the high byte of a big-endian 16-bit word. The other bytes stay 0. The region below `0x400000` is all zeros. `Audio::load_sample_rom` then reads the array as big-endian words into `m_sample_words`.

## Making one sample

`ES5505::generate_one_sample(int32_t output8[8])` runs once for each PCM frame. It clears the eight outputs. Then, for voice 0 up to voice `m_active_voices` (inclusive), it does two steps:

1. `generate_pcm(voice, &output8[pair * 2])` where `pair = (control >> 8) & 3`.
2. `generate_irq(voice, v)`.

The eight outputs are four stereo pairs: 0/1, 2/3, 4/5 and 6/7.

### The steps in `generate_pcm`

If a stop bit is set, nothing happens. Otherwise:

1. The code reads two neighbor words from the ROM: `read_sample(get_integer_addr(accum))` and the next word `get_integer_addr(accum, 1)`. They are signed 16-bit numbers.
2. `interpolate` mixes the two words with the fraction bits (11 bits in the internal format). This is linear interpolation.
3. The accumulator moves by `freqcount`: forward with `+`, backward with `-` (when `DIR` is set).
4. `apply_filters` runs the four-pole filter.
5. The result times the left volume and the right volume goes into the pair outputs. The volume comes from `m_volume_lookup`: an 8-bit code with a 4-bit exponent and a 4-bit mantissa. The formula is `((mantissa | 16) << 11) >> (16 - exponent)`. The product is shifted right by 11.
6. `check_for_end_forward` or `check_for_end_reverse` tests the voice end.

### The four-pole filter

The filter has four poles. The first two are always low-pass poles that use `K1`. The mode bits (`LP4`, `LP3`, in `CR` bits 11 and 10) set the other two:

| Mode | Pole 3 | Pole 4 |
|---|---|---|
| 0 | High-pass, `K2` | High-pass, `K2` |
| 1 | Low-pass, `K1` | High-pass, `K2` |
| 2 | Low-pass, `K2` | Low-pass, `K2` |
| 3 | Low-pass, `K1` | Low-pass, `K2` |

The low-pass function is `(cutoff >> 4) * (out - in) / 4096 + in`. The code keeps the pole state in the voice (`o1n1`, `o2n1`, `o2n2`, `o3n1`, `o3n2`, `o4n1`). The constants `FINE_FILTER_BIT = 16`, `FILTER_BIT = 12` and `FILTER_SHIFT = 4` set the scale.

### Loops and the end of a voice

When the accumulator passes the end address (forward) or the start address (backward):

- If `IRQE` is set, the code sets the `IRQ` bit in `CR`.
- With no loop bits, or with `BLE` only, the code sets `STOP0`. The voice stops.
- With `LPE` only, the accumulator wraps: `start + (accum - end)`.
- With `LPE` and `BLE`, the accumulator reflects and the code toggles `DIR`.

### Voice interrupts

`generate_irq` checks each voice after it generates. If the voice has `IRQ` set and the chip has no pending vector (`m_irqv & 0x80`), the chip stores the voice number in `m_irqv` and clears the voice bit. A read of `IRQV` returns the vector and sets it back to `0x80`.

::: info
The class has an IRQ callback hook (`set_irq_callback`). `Audio` never connects it. The chip interrupt does not reach the sound CPU in this runtime. The only sound CPU interrupt is level 6 from the DUART. The driver can still read `IRQV`.
:::

## Output summary

The sum for one pair is a signed integer of up to 20 bits. `Audio::generate_one_frame` divides it by 524,288 and clamps it. The page about [device time and output](/developer/runtime/audio/timing) shows the rest of the path. Pair 0 goes straight to the mixer. Pairs 1 to 3 go to the [ES5510](/developer/runtime/audio/es5510).

## Reset and state

`ES5505::reset()` sets `m_active_voices` to 31, the page to 0, `m_irqv` to `0x80`, `m_mode` to `0x7f8`, and every voice to stopped (`control = CONTROL_STOPMASK`) with volumes `0x80`. The sample rate becomes `15238090 / 512`, which is 29761.

`Audio::reset_board()` does not call `ES5505::reset()`. The board reset keeps the voices. The tests in `check.cpp` state this: "Board reset restores volume without resetting OTIS voices."

`save_state` and `load_state` transfer all voice fields, banks, rate, clock, page, mode and IRQ state through `CanonicalES5505`.

ROM pointers, lookup tables and callbacks are not serialized. The runtime retains those attachments.

The voice structure includes ramp and envelope fields inherited from the core. This ES5505 generator does not advance them.

Unimplemented register reads return zero; unimplemented writes do nothing. A missing sample ROM returns zero sample words.

`m_mode` stores SERMODE bits but does not alter `generate_one_sample` routing. The output-pair bits in each voice CR select routing.

For driver sample selection and envelope writes, see [sequences and allocation](/developer/runtime/audio/sequences).
