# Each interval below is half-open. Rationale and evidence (self-contained):
#   - "fill = 0xff" is verified against the CPU's program image at load: any
#     differing byte is a generation error, so the FF claims cannot go stale.
#   - Data banks are not proven by entropy. Evidence is: no rooted instruction
#     start, entry or control reference inside; native profile runs over seeds
#     1-8 x 20000 frames; eight-seed parity gates. Absence of sampled execution
#     is not a universal proof; an excluded destination fails loudly at runtime.
#   - Counterexample: excluding main 0x2000..0x3000 on entropy alone (7.69
#     bits/byte) generated fine but broke strict-native at PC 0x2f84. Never
#     exclude a range on entropy alone.

# Emit units: [[video.emit_units]] declares a span of game code (start..end PCs,
# each an even decoded instruction; `unit` = register holding the object address
# at start; `size` = bytes behaviours may access there; `owner`) that draws one
# object or queue record into sprite RAM, giving the runtime stable sprite identity
# and sandbox replay of the game's native code; emulated state, CRCs, cycles and
# native block counts are unchanged. [video.frame_writers] lists inclusive PC
# ranges that write sprite RAM outside any unit. The object loop at 0x9a0e
# sets a6 = object (0x410000 + k*0x80). Per object, 0xa1c8 projects, 0xa334
# rescales zoom and 0x9b32 compiles sprite entries through a4; 0x9a6c is the
# loop's `lea $80(a6),a6`, so [0x9a3c,0x9a6c) draws exactly one object.
