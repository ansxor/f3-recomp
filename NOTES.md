# Runtime decisions

- 2026-10-03: `f3rt` is a standalone C++20 library with a C CPU ABI, SDL3 frontend, software FDP renderer, and permissively licensed Musashi CPU interpreter for independent execution. No MAME framework dependency at runtime.
- Reference is local MAME `taito_f3.cpp` / `taito_f3_v.cpp`, not inferred physical mirrors where MAME disagrees. Main CPU is 16 MHz per MAME; raster is 26,686,000 / 4 Hz, 432 x 262 total, 320 x 232 visible (x=46,y=24). Vblank IRQ2 and delayed IRQ3 (+10,000 main cycles) match MAME. MAME does not implement timer IRQ5; do not introduce physical timer behavior that changes the reference path.
- CPU ABI being frozen with recomp peer: big-endian accessors, explicit CPU context, per-block interrupt boundary, exception entry, generated block dispatch, and interpreter fallback. Runtime owns the published header.
- ROMs, generated C, captures, and decoded assets remain untracked. Raw ROM contents must never be committed.
- Video and audio adaptations must retain upstream attribution and licensing. Renderer correctness is judged against captured MAME frames; audio is checked with executable device/ROM scenarios, not a no-op audio path.

- The supplied `roms/landmakr` is `landmakrj` 2.01J. Orchestrator changed the target accordingly; world `landmakr` loading remains configured but untested. The two short sound program chips become exact current-MAME CRC/SHA1 dumps when their missing upper halves are filled with FF. Four required board PLDs come from supplied Puchi Car dumps with exact matching CRCs; no substitute data is fabricated.
- ABI v1 frozen with peer; initial crossed drafts resolved in `docs/ABI-CHANGES.md`.
- Built standalone runtime and linked generated C. Behavioral smoke passed memory mirrors/byte lanes, input and coin edges, EEPROM write protection and sequential wrap, 68020 IRQ/stack entry, native dispatch, and one-instruction fallback.
- SDL3 actual window run: `video_driver=cocoa renderer=metal`, 120 frames, renderer readback saved under ignored `build/window.bmp`.
- Independent MAME capture works using clean shared baseline. Capture taps require strong Lua references and reset reinstallation; otherwise scroll state is silently lost. `build/captures/mame-verified` is the corrected 25-frame reference (600..3480, step 120).
- Video parity work remains active: corrected doubled RAM offsets and host-word character decoding. Replay now exactly matches 15/25 sampled frames; remaining animated/alpha mismatches are under investigation. No final parity claim.
- Audio remains under investigation: sound CPU runs but initial 3600-frame ROM smoke is silent. Corrected OTIS accumulator mask (31, not 27 bits), CPU-only RESET preservation, and sound CPU cycle-overrun accounting. These are not yet sufficient for attract sound.
- Strengthened acceptance: only an integrated generated-C executable with attract, playable coin/start/input, sound, and MAME parity qualifies as DONE. Recomp peer owns root `integration` branch merges and unified command. Interpreter/replay are validation aids only.
- Canonical CPU state must be imported into Musashi before RESET. Otherwise a native watchdog reset revives the last fallback's D/A/CCR values. Added regression; real ROM native-only rejection also reports PC `0x10000` before executing/counting fallback.
- DUART IRQ transitions must reach the running sound CPU immediately, not just at slice start. The sound ROM entered error `$91` when RTE reaccepted an already-acknowledged timer IRQ; immediate deassertion moves execution past that failure. The external ESP pump halt gate is distinct from the DSP's per-sample halt state.
- Evidence policy updated from CONTEXT: Land Maker ROM behavior and observed output first, then die/datasheets, WIP notes, MAME source. Fetched `y-ack/mame` `fdp-collapse` into the shared clone without touching its checkout. That branch separates FDP/FDA and adds line-controlled 15-bit palette/blur; those differ from baseline master and require ROM-register evidence before enabling. Neither source is treated as hardware ground truth.
- Open execution discrepancy: one-instruction runtime boot writes/verifies the complete EEPROM, including checksum `$85ac`; 512-cycle interpreter slices leave `$ffff` there and show `PUSH TEST SWITCH`. Shared with compiler peer; not hidden by seeding EEPROM or bypassing boot checks.
- Renderer replay now passes all 25 corrected wide-attract captures (600..3480, step 120): 1,856,000/1,856,000 pixels RGB-exact. Earlier residual animation/alpha errors were capture phase, not renderer behavior: state N exactly matched `screen:pixels()` from callback N+1 on 34 consecutive animated frames. Capture protocol v2 defers pixel readback accordingly; prior v1 captures must be regenerated for comparisons.
- Full exception timing now belongs to `f3_exception`, matching the pinned 68EC020 model; the compiler must not add normal instruction cost on a trap path. Divide-by-zero regression verifies 38 cycles, format-2 saved instruction PC, and a real RTE restoring the resume PC/stack.
- Diagnostic main interpretation now hands control back at every instruction, rather than every 512 cycles. An actual 1800-frame SDL run reached animated attract (`cocoa`/`metal`), produced 908,843 audio frames and peak 1286; renderer readback is `build/attract-window.bmp`. This is independent-runtime evidence, not integrated native acceptance.
- Audio gain default follows observed baseline routing: quantized MB87077/78 percent/32 is applied before the ESP and after the pump. The explicit `Audio::GainModel::SingleStage` alternative is an unverified analog-gain experiment. OTIS output clamps at signed 20-bit range before routing; auxiliary output retains float precision.
- Added real sound-ROM write tracing (`tools/mame/audio_trace.lua`) and `f3rt-replay --audio-trace`. A fresh 62-second baseline records 8,911,764 device writes; replay peak 1264 versus baseline 1265. Waveform equivalence remains under investigation; peak agreement is not a parity claim.
- Corrected stream-clock inconsistency: generation used the rational crystal divider (~29761.895 Hz), but SDL/WAV metadata advertised 29761 Hz. Generation now matches the advertised integer rate and the baseline OTIS stream. A ten-second sample-count regression catches drift; waveform analysis must still distinguish device output, host resampling, and game scheduling.
- Native-rate sound-write replay now separates device arithmetic from host resampling: over seconds 18–54, both channels correlate at 0.999978 with MAME after a one-sample latency correction; RMS error is 1.306/1.264 PCM LSB and channel peaks match at 1239/1264. `tools/compare_audio.py` reproduces fixed-latency metrics without fitting gain or warping time. Integrated-game sound remains a separate check.
- Corrected signed PCM conversion to scale by 32768 and saturate, rather than scale by 32767. A DC-voice regression failed before and passes after; it also checks independent channel mute, baseline two-stage attenuation, and explicit single-stage gain.
- EEPROM busy timing caused the seven-frame cold-boot lead. Serial pins/readback now use absolute main CPU cycles; word write is 1750us, word erase 1000us, and bulk operations 8000us, matching the observed baseline model. CS polling exposes busy; serial command edges cannot start another command before completion. Power reset clears timing while preserving words.
- After EEPROM timing, a fresh 3600-frame independent ROM boot matches 20/25 phase-aligned MAME frames exactly; total differences fall to 7,303/1,856,000 RGB pixels, concentrated in five animated frames. Early logo/brightness differences disappear. The leading audio offset falls from ~118ms to ~0.4ms through seconds 20–45; later event scheduling and residual animated-frame differences remain open. Artifacts: `build/captures/eeprom-timed`, `build/eeprom-timed.wav`.
- Reused MAME tap handles with `reinstall()` instead of replacing live handles on reset. Before the change, a native-rate trace contained 20,816 exactly duplicated adjacent writes; the fresh 8,890,949-write trace has none. Fresh combined audio/video capture still replays all 25 frames RGB-exact, and the native-rate audio metrics are unchanged.
- Sound CPU slices now end at OTIS sample boundaries so later register writes in a fixed 512-tick slice cannot affect an earlier sample. A full 3600-frame ROM smoke preserves final PC/frame CRC and output count; this does not resolve the separate integrated music-event timing differences.
- Recompiler peer traced the remaining sprite differences to idle-loop RNG state: ROM `$1468` updates seed RAM `$400826`, called repeatedly by the `$19f8` idle loop until IRQ. One-instruction native execution reproduces the independent interpreter's five differing frames. No RNG seed override or diff masking was introduced.
- Main reset debt was previously discarded by canonical-state import. `Interpreter::reset_main` now consumes the core's reset-only slice and charges all four cycles before export. Cold and warm reset regressions verify the charge without executing an opcode; the real 600-frame cold boot still reaches `$1136`. This corrects the reset epoch but is not yet claimed to eliminate RNG differences.
- Whole-machine/watchdog reset now has a separate `Audio::reset_board` path from the sound CPU's MMIO reset line. The pinned baseline resets DUART, DSP memories and volume, reloads boot vectors, but preserves sound work RAM and OTIS state. A watchdog regression failed before the fix (DUART vector retained) and now passes; CPU-only reset preservation, DSP clearing, volume restoration and vector reload are covered.
- Audio traces are now `F3AUD2`, recording whole-board resets as well as writes. The fresh baseline records resets at ticks 0 and 82,212,786, with 8,890,949 writes and no duplicate writes. Reset-aware device replay retains correlation 0.999978 and RMS error 1.306/1.264 PCM LSB. A real 3600-frame independent boot reaches `$1136`, peak 1267, and 1,817,643 audio frames; it still differs in five animated reference frames (7,011 pixels), so this reset correction is not an integrated parity claim.
