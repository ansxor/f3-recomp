# Recompiler decisions

- 2026-10-03: MAME `taito_f3.cpp` lines 4166–4171 defines World `landmakr` as four 0x80000-byte lanes e61-19.20, e61-18.19, e61-17.18, e61-16.17, interleaved at byte offsets 0,1,2,3. Supplied `roms/landmakr` instead contains e61-13.20, e61-12.19, e61-11.18, e61-10.17: MAME `landmakrj`. Keep distinct validated game configurations; never silently identify Japan as World. Runtime peer and orchestrator notified.
- Orchestrator subsequently approved Japan `landmakrj` (2.01J) as the actual execution target. World remains configuration-only and untested; no additional ROMs will arrive. This resolves the ROM-scope discrepancy rather than blocking the Japanese milestone.
- N64Recomp design reference: https://github.com/N64Recomp/N64Recomp — literal instruction lowering, metadata-guided discovery, per-game TOML, runtime-resolved indirect transfers. N64ModernRuntime reference: https://github.com/N64Recomp/N64ModernRuntime — separate hardware implementation and recompilation bridge. F3 flat ROM needs no relocatable overlays unless RAM execution is observed; unresolved/RAM PCs go through explicit runtime fallback, not invented relocation metadata.
- Dispatch uses emulated PC and stack, never native recursive calls. Basic-block boundary callback permits IRQ delivery without retaining stale PC/flags. Lazy flags must materialize before exceptions or external state observation.
- Source and verification tools are committed. ROM bytes, generated game C, third-party downloaded reference builds, and generated traces remain ignored.
- ABI v1 is now agreed byte-for-byte with the runtime peer: `include/f3rt/cpu_abi.h`, including active/inactive stacks, 020 control registers, opaque runtime pointer, lazy flag fields, cumulative scheduling cycles, runtime-owned sorted dispatch lookup, and one-instruction fallback. Only memory callbacks accept pending flags; other callbacks require canonical SR.
- Python Capstone 5.0.9 is installed into ignored `build/python` for this workstation (`PYTHONPATH=build/python`). The workstation's Python 3.13 `venv`/uv inspection failed due to empty `platform.mac_ver()`; `/usr/bin/python3 -m pip install --target build/python capstone==5.0.9` succeeded. This is an environment workaround, not a package runtime dependency.
- Initial compiler smoke: strict Japan lane load succeeds; World config fails explicitly on missing `e61-19.20`. Discovery: 21,373 instructions, 79,734 unique bytes / 2 MiB (3.802%), 563 candidate functions, 55 unresolved transfers, 18 vector/config seeds and 58 heuristic seeds. This does not certify unknown bytes as data.
- C emission smoke: 21,284 native instruction entries and 89 explicit fallback entries, 6,707 bounded native blocks. All 54 generated translation units compile into `build/native/libf3_recompiled.a` with Clang `-O3 -Wall -Wextra -Werror`; generated output remains ignored.
- Differential validation observed 4,996 passed / 0 failed, with four bitfield instructions reported unsupported (not passes), from 5,000 deterministic cases. Includes multi-instruction lazy flag transitions; native cases run with UBSan and warnings as errors. Earlier failing regressions caught and fixed postincrement, aliased stack/source EAs, SR/CCR privilege and flag preservation, MOVEM base-in-list/order, PC-relative extension position, full-format PC indexing, ASL width-count overflow, and long DIV remainder/overflow.
- Capstone 5.0.9 has two relevant detail limitations: full-format PC-relative EA may be labelled AREGI_INDEX with `base_reg=PC` (never A16); 32/32 long DIV hides the distinct remainder register. Lowering handles these from the PC register identifier and raw extension word respectively.
- MAME parity, not undocumented hardware guesses: MAME and Musashi preserve the original base register value in MOVEM predecrement transfers, including its low-word-first long writes. Word DIV overflow differs in unpatched upstream Musashi: current MAME clears C before division while retaining undefined N/Z. Runtime peer owns the corresponding four-template reference-core patch. Arithmetic traps use 68020 format-2 frames, with next PC and instruction PC distinct.
- Integration acceptance is stricter than standalone milestones: root `integration` merges both branches, and only generated-C `landmakr` with no main-CPU fallback, attract, coin/start/controls, sound, and observed-output parity qualifies as DONE. The runtime capture script supersedes the initial compiler capture script because it retains taps and survives ROM-requested soft reset without duplicate callbacks.
- Actual-ROM lockstep first diverged at instruction 6,678,642, PC `0x4444`: Capstone reported full-format word base displacement `0xfa26` unsigned. Raw extension decoding now sign-extends base/outer words, handles MOVE's two EA extensions, and recognizes Capstone's zero-displacement brief-format misclassification. Regression cases cover these separately.
- Native bitfields (all eight operations), CMP2/CHK2, MOVEC, and RTE format 0/1/2 now lower without interpreter calls. The 5,000-case differential run passed all 5,000 with no unsupported cases, including 768 dynamic bitfield boundary cases. Bus-fault/coprocessor RTE formats remain outside the runtime's exception model; they raise format error as the reference Musashi does.
- After the runtime's stale-context watchdog reset fix, 50,000,000 actual-ROM instruction boundaries matched D/A/PC/SR and periodic RAM/device-buffer state through frame 1545. This semantic test synchronizes native time to reference time; it does not prove native timing or video/audio parity. Discovery still missed 1,265,436 executed instructions in that run, serviced by the diagnostic fallback; this is not native-only acceptance.
- Evidence priority correction: Land Maker ROM behavior plus its observed MAME output first; primary die/datasheet evidence next; WIP Taito F3 notes next; MAME source last. Neither notes nor MAME source is hardware ground truth. Runtime owns FDP source comparisons; conflicting choices must be recorded and switchable. Clean MAME baseline is the observable comparison target, not a claim of physical fidelity.
- Native boot exposed a scheduling requirement: the nominal four-tick model reached `PUSH TEST SWITCH`; reference opcode costs instead initialized EEPROM checksum `$85ac`, reached the animated Japanese tutorial at frame 3600, and produced nonzero audio (peak 312). This is a real boot change, not EEPROM seeding or bypassing the ROM check.
- `recomp/timing.py` now emits pinned 68EC020 instruction costs from non-ROM Musashi descriptors, with MOVEM/full-EA/branch/DBcc/rotate adjustments. `tools/differential/export_cycles.py` reproduces the CSV from the generated reference table. Differential checks now compare elapsed cycles as well as architectural state and memory: all 5,000 passed; regenerated metadata matched byte-for-byte.
- Actual-ROM verification expanded to 120,000,000 single-instruction boundaries through frame 3941 and 10,000,000 multi-instruction native blocks through frame 500. Both passed state comparison against independent instruction stepping. The latter validates lazy-flag sequences in real generated blocks; reference clocks remain synchronized in these semantic checks.
- Discovery metadata now records 125 indirect continuation runs from the long ROM trace, plus 12 additional continuations exercised by correctly timed native attract. A zero-fallback run must be repeated after every coverage extension; a diagnostic run that found missing PCs is not the final native-only proof.
- A strict integrated run exposed callback `0x0a53f8`, whose pointer is actor bytecode data rather than a direct 68020 transfer. Decoded the actual ROM interpreter at `0x409e` and its handler table at `0x40aa`: commands 0–4 carry native callbacks; 5/9/10 are script jump/call/return. TOML now describes operand widths, control-flow opcodes, and actor script-pointer field `0x1c`; discovery follows bounded visited script addresses instead of instruction-decoding their data.
- Script-aware discovery finds 37,659 instructions / 138,528 bytes (6.606%), 1,628 candidate functions and 86 unresolved transfers; all discovered instructions lower natively. A 4,800-frame generated-C ROM run completed with 69,190,209 native blocks, zero fallback instructions, visible attract, and nonzero audio peak 1287. Root strict-binary verification and playable input remain separate acceptance checks.
- Real SDL coin/start/character-selection input reached previously undiscovered actor callbacks `$a5614` and `$a27ce`. The initializer consumer at `$3a76..$3a88` indexes a 60-entry native function table at `$d0de4`. Discovery now reads its bounded TOML table metadata, and follows direct/register-staged PC-indexed script-pointer loads, including `{script,counter}` records at `$a26f2`. This expands generated coverage to 39,271 instructions / 145,888 bytes (6.956%); all discovered instructions lower natively. Strict gameplay verification remains required after this expansion.
- Root strict native execution with runtime `f02355d` completed 4,800 frames, 69,190,209 native blocks, zero fallback instructions, and nonzero audio peak 1252 (`build/native-final.wav`). Same-index frame comparison still differed; dense capture proved MAME frame 1080 equals native frame 1073 RGB-exact. Runtime EEPROM lacks the MAME-observed 1.75 ms per-word busy interval; 64 startup writes account for roughly this seven-frame lead. Runtime peer owns the busy-timing fix; no artificial frame offset or boot delay is being added.
- Native gameplay exposed generic table-discovery gaps: destinations before a pointer table prematurely ended scanning; register-staged `MOVEA table(PC,Xn),An; JMP (An)` and `LEA table(PC,Xn),An; JMP ([An])` were unresolved. Bounded scanning now handles these. Capstone also returns unsigned full-extension word displacements: `$f8d36` uses displacement `-32` to read `$f8d18`, not the displayed `$108d18`. Discovery now parses raw displacement widths/signs and outer offsets. Four synthetic-ROM regressions cover script cycles, long callbacks, staged script records, backward jump destinations, and the negative full extension.

# Runtime decisions

- 2026-10-03: `f3rt` is a standalone C++20 library with a C CPU ABI, SDL3 frontend, software FDP renderer, and permissively licensed Musashi CPU interpreter for independent execution. No MAME framework dependency at runtime.
- Reference is local MAME `taito_f3.cpp` / `taito_f3_v.cpp`, not inferred physical mirrors where MAME disagrees. Main CPU is 16 MHz per MAME; raster is 26,686,000 / 4 Hz, 432 x 262 total, 320 x 232 visible (x=46,y=24). Vblank IRQ2 and delayed IRQ3 (+10,000 main cycles) match MAME. MAME does not implement timer IRQ5; do not introduce physical timer behavior that changes the reference path.
- CPU ABI being frozen with recomp peer: big-endian accessors, explicit CPU context, per-block interrupt boundary, exception entry, generated block dispatch, and interpreter fallback. Runtime owns the published header.
- ROMs, generated C, captures, and decoded assets remain untracked. Raw ROM contents must never be committed.
- Video and audio adaptations must retain upstream attribution and licensing. Renderer correctness is judged against captured MAME frames; audio is checked with executable device/ROM scenarios, not a no-op audio path.

- The supplied `roms/landmakr` is `landmakrj` 2.01J. Orchestrator changed the target accordingly; world `landmakr` loading remains configured but untested. The two short sound program chips become exact current-MAME CRC/SHA1 dumps when their missing upper halves are filled with FF. Four required board PLDs come from supplied Puchi Car dumps with exact matching CRCs; no substitute data is fabricated.
- ABI v1 frozen with peer; initial crossed drafts resolved in `docs/ABI-CHANGES.md`.
- Built standalone runtime and linked generated C. Behavioral smoke passed memory mirrors/byte lanes, input and coin edges, EEPROM write protection and sequential wrap, 68020 IRQ/stack entry, native dispatch, and one-instruction fallback.
- SDL3 actual window run: `video_driver=cocoa renderer=metal`, 120 frames, renderer readback saved under ignored `build/window.bmp`.
- Independent MAME capture works using clean shared baseline. Capture taps require strong Lua references and reset reinstallation; otherwise scroll state is silently lost. `build/captures/mame-verified` is the corrected 25-frame reference (600..3480, step 120).
- Video parity work remains active: corrected doubled RAM offsets and host-word character decoding. Replay now exactly matches 15/25 sampled frames; remaining animated/alpha mismatches are under investigation. No final parity claim.
- Audio remains under investigation: sound CPU runs but initial 3600-frame ROM smoke is silent. Corrected OTIS accumulator mask (31, not 27 bits), CPU-only RESET preservation, and sound CPU cycle-overrun accounting. These are not yet sufficient for attract sound.
- Strengthened acceptance: only an integrated generated-C executable with attract, playable coin/start/input, sound, and MAME parity qualifies as DONE. Recomp peer owns root `integration` branch merges and unified command. Interpreter/replay are validation aids only.
- Canonical CPU state must be imported into Musashi before RESET. Otherwise a native watchdog reset revives the last fallback's D/A/CCR values. Added regression; real ROM native-only rejection also reports PC `0x10000` before executing/counting fallback.
- DUART IRQ transitions must reach the running sound CPU immediately, not just at slice start. The sound ROM entered error `$91` when RTE reaccepted an already-acknowledged timer IRQ; immediate deassertion moves execution past that failure. The external ESP pump halt gate is distinct from the DSP's per-sample halt state.
- Evidence policy updated from CONTEXT: Land Maker ROM behavior and observed output first, then die/datasheets, WIP notes, MAME source. Fetched `y-ack/mame` `fdp-collapse` into the shared clone without touching its checkout. That branch separates FDP/FDA and adds line-controlled 15-bit palette/blur; those differ from baseline master and require ROM-register evidence before enabling. Neither source is treated as hardware ground truth.
- Open execution discrepancy: one-instruction runtime boot writes/verifies the complete EEPROM, including checksum `$85ac`; 512-cycle interpreter slices leave `$ffff` there and show `PUSH TEST SWITCH`. Shared with compiler peer; not hidden by seeding EEPROM or bypassing boot checks.
- Renderer replay now passes all 25 corrected wide-attract captures (600..3480, step 120): 1,856,000/1,856,000 pixels RGB-exact. Earlier residual animation/alpha errors were capture phase, not renderer behavior: state N exactly matched `screen:pixels()` from callback N+1 on 34 consecutive animated frames. Capture protocol v2 defers pixel readback accordingly; prior v1 captures must be regenerated for comparisons.
- Full exception timing now belongs to `f3_exception`, matching the pinned 68EC020 model; the compiler must not add normal instruction cost on a trap path. Divide-by-zero regression verifies 38 cycles, format-2 saved instruction PC, and a real RTE restoring the resume PC/stack.
- Diagnostic main interpretation now hands control back at every instruction, rather than every 512 cycles. An actual 1800-frame SDL run reached animated attract (`cocoa`/`metal`), produced 908,843 audio frames and peak 1286; renderer readback is `build/attract-window.bmp`. This is independent-runtime evidence, not integrated native acceptance.
- Audio gain default follows observed baseline routing: quantized MB87077/78 percent/32 is applied before the ESP and after the pump. The explicit `Audio::GainModel::SingleStage` alternative is an unverified analog-gain experiment. OTIS output clamps at signed 20-bit range before routing; auxiliary output retains float precision.
- Added real sound-ROM write tracing (`tools/mame/audio_trace.lua`) and `f3rt-replay --audio-trace`. A fresh 62-second baseline records 8,911,764 device writes; replay peak 1264 versus baseline 1265. Waveform equivalence remains under investigation; peak agreement is not a parity claim.
- Corrected stream-clock inconsistency: generation used the rational crystal divider (~29761.895 Hz), but SDL/WAV metadata advertised 29761 Hz. Generation now matches the advertised integer rate and the baseline OTIS stream. A ten-second sample-count regression catches drift; waveform analysis must still distinguish device output, host resampling, and game scheduling.
- Native-rate sound-write replay now separates device arithmetic from host resampling: over seconds 18–54, both channels correlate at 0.999978 with MAME after a one-sample latency correction; RMS error is 1.306/1.264 PCM LSB and channel peaks match at 1239/1264. `tools/compare_audio.py` reproduces fixed-latency metrics without fitting gain or warping time. Integrated-game sound remains a separate check.
- Corrected signed PCM conversion to scale by 32768 and saturate, rather than scale by 32767. A DC-voice regression failed before and passes after; it also checks independent channel mute, baseline two-stage attenuation, and explicit single-stage gain.
- EEPROM busy timing caused the seven-frame cold-boot lead. Serial pins/readback now use absolute main CPU cycles; word write is 1750us, word erase 1000us, and bulk operations 8000us, matching the observed baseline model. CS polling exposes busy; serial command edges cannot start another command before completion. Power reset clears timing while preserving words.
- After EEPROM timing, a fresh 3600-frame independent ROM boot matches 20/25 phase-aligned MAME frames exactly; total differences fall to 7,303/1,856,000 RGB pixels, concentrated in five animated frames. Early logo/brightness differences disappear. The leading audio offset falls from ~118ms to ~0.4ms through seconds 20–45; later event scheduling and residual animated-frame differences remain open. Artifacts: `build/captures/eeprom-timed`, `build/eeprom-timed.wav`.
- Reused MAME tap handles with `reinstall()` instead of replacing live handles on reset. Before the change, a native-rate trace contained 20,816 exactly duplicated adjacent writes; the fresh 8,890,949-write trace has none. Fresh combined audio/video capture still replays all 25 frames RGB-exact, and the native-rate audio metrics are unchanged.
- Sound CPU slices now end at OTIS sample boundaries so later register writes in a fixed 512-tick slice cannot affect an earlier sample. A full 3600-frame ROM smoke preserves final PC/frame CRC and output count; this does not resolve the separate integrated music-event timing differences.
- Recompiler peer traced the remaining sprite differences to idle-loop RNG state: ROM `$1468` updates seed RAM `$400826`, called repeatedly by the `$19f8` idle loop until IRQ. One-instruction native execution reproduces the independent interpreter's five differing frames. No RNG seed override or diff masking was introduced.
- Main reset debt was previously discarded by canonical-state import. `Interpreter::reset_main` now consumes the core's reset-only slice and charges all four cycles before export. Cold and warm reset regressions verify the charge without executing an opcode; the real 600-frame cold boot still reaches `$1136`. This corrects the reset epoch but is not yet claimed to eliminate RNG differences.
